# Интернет‑магазин (учебный проект)

## Описание проекта


Это учебный проект:

1) интернет‑магазина, разрабатываемый в рамках курса. 

2) Веб‑приложение с блогом

Проект будет поэтапно дорабатываться на каждом занятии. 

В итоге должен получиться полноценный веб‑магазин и  Веб‑приложение с блогом.

Интернет‑магазин включает модели Product (товар) и Category (категория), админку, фильтрацию и поиск, миграции, 
фикстуры и кастомную команду для заполнения БД тестовыми данными. В форме добавлены валидация и стилизация.
Для сервиса интернет-магазина реализована функция аутентификации пользователей, чтобы боты не могли вмешиваться
в работу сервиса. Доступ к страницам, связанным с управлением продуктами, для анонимных пользователей закрыт. 
Только авторизованные пользователи могут просматривать, создавать, изменять и удалять продукты. 
Общедоступна только страница просмотра списка товаров.

Продукты проходят ручную модерацию: новые товары создаются неопубликованными (status_publication=False),
а модераторы управляют их публикацией. Реализована группа «Модератор продуктов» с правами на снятие с публикации
(can_unpublish_product) и удаление любого продукта (delete_product). Редактирование и удаление доступны только
владельцу продукта, удаление — также модератору.

Веб‑приложение с блогом  включает модели блоговой записи Blog, админку, фильтрацию и поиск, миграции

### Модели для магазина с товарами
* Category (категория)

Поля:

name — наименование (строка, макс. 100 символов).

description — описание (текст, макс. 1000 символов).

slug — слаг для URL (строка, до 120 символов): заполняется автоматически из названия, если не задан.

* Product (товар)

Поля:

name — наименование (строка, макс. 100 символов).

description — описание (текст, макс. 1000 символов).

image — изображение (поле ImageField, загрузка в /image/).

category — связь с Category (ForeignKey, каскадное удаление).

price — цена (десятичное число, 2 знака после запятой).

created_at — дата создания (автоматически).

updated_at — дата последнего изменения (автоматически).

status_publication — статус публикации (BooleanField, default=False): новый продукт создаётся неопубликованным.

owner — владелец продукта (ForeignKey на пользователя): заполняется автоматически текущим авторизованным пользователем при создании.

Кастомное право (Meta.permissions):

can_unpublish_product — возможность снять продукт с публикации (для модераторов).

* Contact (контактная информация)

Поля:

phone — телефон.

email — email.

address — адрес.

working_hours — часы работы.


###

### Модели для блога со статьями
* Blog (блог со статьями)

Поля:

title (CharField, до 200 символов) — заголовок записи.

description (TextField, до 1000 символов) — основное содержимое записи.

image (ImageField) — изображение‑превью:

загружается в папку image/ (относительно MEDIA_ROOT);

необязательное поле (blank=True).

created_at (DateTimeField) — дата и время создания записи:

заполняется автоматически при создании (auto_now_add=True).

updated_at (DateTimeField) — дата и время последнего изменения:

обновляется автоматически при каждом сохранении (auto_now=True).

publication (BooleanField) — признак публикации:

    True — запись опубликована;
    
    False — черновик (значение по умолчанию).

counter_views (PositiveIntegerField) — счётчик просмотров:

по умолчанию равен 0 (default=0);

может принимать значение NULL (null=True).



### Роли и права доступа

Группа «Модератор продуктов» создаётся кастомной командой:

```
python manage.py create_groups
```

Группа включает права:

- can_unpublish_product — снятие продукта с публикации (модератор редактирует только статус публикации);
- delete_product — удаление любого продукта.

Правила доступа к управлению продуктами:

- Создание — любой авторизованный пользователь; продукт автоматически привязывается к владельцу.
- Редактирование — только владелец продукта (полная форма) и модератор (только статус публикации).
- Удаление — владелец продукта и модератор.
- В шаблонах кнопки «Редактировать» и «Удалить» отображаются только для владельца, «Удалить» — также для модератора.

## Кеширование (Redis)

Проект использует Redis как хранилище кеша (`django-redis`, база №1).

Настройки — в `config/settings.py`, значения читаются из `.env`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `REDIS_URL` | `redis://127.0.0.1:6379/1` | Адрес Redis и номер базы |
| `CACHE_TTL` | `300` | Общий TTL кеша, секунды |
| `PRODUCT_DETAIL_CACHE_TTL` | `300` | TTL страницы продукта |
| `CATEGORY_PRODUCTS_CACHE_TTL` | `300` | TTL списка продуктов категории |

Что кешируется (низкоуровневое кеширование через `django.core.cache`):

- `product_detail_{id}` — страница одного продукта (`ProductDetailView`);
- `category_{id}` — список продуктов категории (сервис `get_products_by_category`).

Кеш сбрасывается сигналами `post_save` / `post_delete` модели `Product`
(`catalog/signals.py`). Если Redis недоступен, сайт продолжает работать
(`IGNORE_EXCEPTIONS`), данные читаются из БД.

## Установка:

1 Клонируйте репозиторий:
``` git clone git@github.com:lidiar8r-ops/home_work_shop.git  ```

2 Перейдите в папку проекта:
``` cd ваш_репозиторий```

3 Установите зависимости:
``` pip install -r requirements.txt```

3.1 Запустите Redis (должен отвечать на `PING` → `PONG`):

```
redis-server
```

Проверка: `redis-cli ping`. Адрес задаётся в `.env` (`REDIS_URL`).

4 Примените миграции (создаст таблицы в базе данных):

```
python manage.py makemigrations
python manage.py migrate
```
5 Создайте администратора сайта (чтобы зайти в админку):

```
python manage.py createsuperuser
Введите имя, почту и пароль.
```

6 В терминале запустите сервер:
```python manage.py runserver```
7 Создайте группу «Модератор продуктов» с правами:
```python manage.py create_groups```
8 Откройте в браузере:

для магазина с товарами 
[http://127.0.0.1:8000/](http://127.0.0.1:8000/)

для блога со статьями 
http://127.0.0.1:8000/blogs/
 
для админки [http://127.0.0.1:8000/admin](http://127.0.0.1:8000/admin)



* через кастомную команду, в терминале запустите 
```
python manage.py add_products
```
Для корректной загрузки данных сначала создайте пользователя (например, командой `python manage.py csu`
или `createsuperuser`) — продукты фикстуры будут привязаны к нему как к владельцу.
